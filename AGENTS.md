# Criterios de desarrollo

Preferencia explícita del usuario para el trabajo presente y futuro en este proyecto: desarrollar con claridad, eficiencia, estructura y buenas prácticas, manteniendo el código y las carpetas organizados.

## Organización y arquitectura

- Revisar la estructura existente antes de modificarla y mantener convenciones coherentes.
- Organizar por responsabilidades y funcionalidades; separar interfaz, lógica de negocio, datos, estilos y pruebas cuando corresponda.
- Usar nombres descriptivos, módulos enfocados y funciones pequeñas y legibles.
- Evitar archivos monolíticos, dependencias globales innecesarias, duplicación y acumulación de parches o estilos superpuestos. Consolidar las partes afectadas cuando el alcance lo justifique.
- Mejorar la estructura de forma gradual, preservando los datos y el comportamiento que utiliza el usuario.

## Calidad y eficiencia

- Priorizar soluciones simples, mantenibles y proporcionales a la necesidad. Evitar abstracciones y dependencias sin utilidad concreta.
- Evitar cálculos repetidos, renderizados innecesarios y accesos costosos; optimizar con base en el comportamiento y mediciones cuando sea necesario.
- Validar entradas, manejar errores y mantener prácticas de seguridad y accesibilidad apropiadas.
- Documentar decisiones relevantes y mantener actualizadas las instrucciones de ejecución.
- Ejecutar las comprobaciones y pruebas pertinentes al cambio, con especial atención a fechas, escalas, persistencia y conexiones entre vistas.
- Comunicar qué se cambió, cómo se verificó y cualquier limitación real.

Estas preferencias orientan las tareas autorizadas; no implican reestructurar todo el proyecto ante cada solicitud ni publicar cambios sin una petición que lo autorice.
